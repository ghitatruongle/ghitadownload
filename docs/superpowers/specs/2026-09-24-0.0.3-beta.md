# 0.0.3-beta Release Specification

## Goal

Ship a Windows beta release of Ghita Downloader as `0.0.3-beta` without changing the existing download formats or CLI contract, while making the installer and tool bootstrap paths reliable enough for users to test safely.

## Scope

Included in this beta:

- Synchronize the crate version, installer banner, CLI-reported version, documentation, and release artifact naming to `0.0.3-beta`.
- Make the release build fail visibly when the main executable or `yt-dlp.exe` cannot be embedded, instead of silently producing an installer with `NO_EMBED` payloads.
- Make installer file-copy and setup failures produce non-zero process exit codes; a silent-install run must not report success when the application is unusable.
- Allow `ghitadownload --update-ytdlp` to create the missing `yt-dlp.exe` in the standard installation directory without requiring FFmpeg first.
- Restore `AppConfig.last_output_dir` when the interactive UI starts, falling back to the current working directory only when no saved directory is available or the saved value is invalid.
- Add deterministic tests for the version, CLI update path, output-directory selection, and release build checks that do not require an external download.
- Add a changelog entry describing beta changes and document the beta upgrade path.

Explicitly out of scope for this beta:

- New audio/video formats, quality tiers, or platform providers.
- Changes to Spotify, YouTube, Suno, or social-media extraction behavior.
- A new GUI, packaging installer framework, code-signing certificate, or GitHub Actions workflow.
- Pinning a new FFmpeg or yt-dlp version by checksum; that requires a separate dependency-release decision.

## Release constraints

- Target Windows x64 with the existing `.exe` installer and `Release/ghitadownload_0.0.3-beta.exe` artifact.
- The main binary must be built before the setup binary.
- The release build must not publish or commit an installer whose embedded payload is `NO_EMBED`.
- Existing command-line flags and exit-code meanings remain unchanged: `0` means success and `1` means failure or unresolved failed tasks.
- Existing user configuration remains backward compatible with the current JSON schema.

## Acceptance criteria

1. `cargo test` passes without changing the existing network- and FFmpeg-dependent test policy.
2. `ghitadownload --version` and the main UI report `0.0.3-beta`.
3. A clean release build with a valid `bin/yt-dlp.exe` produces a setup executable containing both valid payloads.
4. A release build without a valid `bin/yt-dlp.exe` fails with an actionable error and a non-zero exit code.
5. `ghitadownload --update-ytdlp` can bootstrap a missing yt-dlp file without prompting for FFmpeg.
6. Starting the interactive UI uses the saved output directory when valid, otherwise the current directory.
7. A silent installer run exits non-zero on a required file-copy or directory-creation failure.
8. `Release/ghitadownload_0.0.3-beta.exe` exists, passes a size/PE smoke check, and its SHA-256 is recorded in the release notes or manifest.
9. The working tree contains no `0.0.2` release references that are intended to describe the active beta release.
