# 0.0.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Ghita Downloader `0.0.4` with Suno playlist pagination, Ctrl+C cancellation, async-native Suno decrypt, cookies/metadata/Opus/manifest features, shared fs/regex/HTTP utilities, and a hardened CI pipeline.

**Architecture:** Keep the existing two-binary crate, `BatchProcessor` pipeline (resolve → execute → task), yt-dlp/FFmpeg process wrappers, and inquire UI. Add a small `utils/fs.rs`, `core/ytdlp.rs`, and `core/manifest.rs` modules; route cancellation through a `tokio_util`-free `CancellationToken` implemented on `tokio::sync::watch` or `Arc<AtomicBool>` plus child-process kill. Do not introduce new crates except `tokio-util` only if strictly required; prefer std+tokio primitives.

**Tech Stack:** Rust 2021, Cargo, Clap 4, Tokio, reqwest, serde_json, yt-dlp, FFmpeg, PowerShell/batch.

**Spec:** `docs/superpowers/specs/2026-10-03-0.0.4.md`

## Global Constraints

- Package version exactly `0.0.4`; artifact `Release/ghitadownload_0.0.4.exe`.
- Existing CLI flags, format/quality values, exit codes, `AppConfig`/`FailedQueue` JSON remain compatible.
- No comments (`//`, `///`, `/* */`) in `src/`, `tests/`, `build.rs`.
- No `git commit`/`git push` unless the user asks; README headings keep no icons; `AGENT.md` stays gitignored.
- `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo test --locked` must pass at the end of each task batch.
